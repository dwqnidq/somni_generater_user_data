# Somni 用户数据仓库 — AI 代码质量与收尾

本 Skill 约束在本仓库内由 Agent 编写或修改代码时的行为，并在收尾阶段强制自检。

## 1. 编写阶段（改动约束）

- **范围**：只改完成任务所必需的文件与行数；禁止顺带重构、格式化无关文件、扩大需求外的「顺手清理」。
- **一致性**：修改前先读被改文件邻近逻辑；命名、类型风格、import 顺序、注释语言与密度须与周围代码一致。
- **可维护性**：避免复制粘贴大块重复逻辑；能复用仓库内已有函数则复用。禁止为显而易见的一行加冗长注释或 docstring。
- **诚实性**：不臆造 Mongo/API/环境变量名；不确定时先 `Grep`/`Read` 确认调用方与配置来源。
- **大文件**：`generate_health_data.py` 等超大文件只编辑必要片段，避免无意义全文件重写。

## 2. 收尾阶段（改完后必做）

在宣称「完成」「已修复」「可以通过」之前，**必须**完成下列检查（按适用性执行，并在回复中简要说明结果）：

1. **静态与诊断**：对本次修改过的路径调用工作区诊断（如 `read_lints`）；若有新增问题，修到干净或明确说明无法消除的原因（例如上游工具误报）。
2. **语法**：对改动过的 `.py` 执行 `python -m py_compile <文件>` 或通过等价方式确认无语法错误。
3. **测试（若相关）**：若改动影响可测逻辑，在 `test/` 下运行**相关**用例（例如 `pytest test/test_xxx.py -q`）；若无测试覆盖，说明风险并建议最小补测或手动验证步骤。
4. **运行路径**：若改了入口脚本或 import 链，用最短命令做一次导入或 `--help` 级烟测，避免 `ModuleNotFoundError` 等低级错误遗留。

## 3. 删除无用代码

- **未使用的 import / 变量 / 函数**：在确认无引用后删除；若仅「可能」未使用，先用搜索确认再删。
- **注释掉的死代码块**：若已长期不用且无文档价值，删除；若保留有助于理解边界情况，保留并简短说明原因。
- **不要删除**：用户未要求删除的他人注释、与本次任务无关但仍在用的分支；不要为了「变短」而删测试或配置样例。

## 4. 针对 AI 的额外约束

- **证据先于结论**：声称通过或修复时，应基于实际命令/诊断输出，而非推测。
- **环境与密钥**：不把真实密钥、token、完整连接串写入仓库或聊天可复制块；沿用 `.env` 与现有读取方式。
- **数据与 IO**：写文件时用仓库已有工具（如 `atomic_write_json` 等）若场景匹配；避免静默覆盖大量生成物而不说明。
- **回复语言**：与用户对话语言保持一致（本仓库协作者常用中文时，说明与总结用中文）。

## 5. 完成前自检清单（复制勾选）

```
- [ ]  diff 仅覆盖需求范围，无无关文件
- [ ]  已查看修改文件的 linter/诊断
- [ ]  已 py_compile 或通过等价语法检查
- [ ]  已删除确认无用的 import/死代码，或说明保留原因
- [ ]  已运行相关测试或说明未覆盖原因
- [ ]  未引入虚构 API/配置名
```
