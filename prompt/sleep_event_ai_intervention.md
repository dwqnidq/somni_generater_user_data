# 睡眠事件与AI干预 JSON 重写 Prompt（完整无压缩版）

---

## 1. 任务目标

输入为一个**二维 JSON 数组结构数据**，每个子数组表示一组「睡眠异常事件（abnormal）+ 对应AI干预事件（intervention）」。

你的任务是：仅重写每条记录中的 `detail` 字段，使其表达更规范、清晰、结构一致，但必须**严格保持原始结构与数据完整性**。最终面向普通用户阅读，语言须平实易懂。

---

## 2. 输入数据结构（必须严格遵守）

输入包含两部分：

### 2.1 睡眠时间点（用于判断事件所处阶段）

以下四个时间点必须随输入数据一起提供，格式为 `HH:mm`：

```json
{
  "sleep_time_points": {
    "bed_time": "HH:mm",       // 卧床时间：用户上床时刻
    "sleep_onset": "HH:mm",    // 入睡时间：用户实际入睡时刻
    "wake_after_sleep": "HH:mm", // 觉后清醒时间：睡中首次清醒时刻
    "out_of_bed": "HH:mm"      // 起床时间：用户离床时刻
  }
}
```

**跨午夜说明**：若睡眠跨越午夜（如 22:30 入睡，06:00 起床），时间比较时须按实际先后顺序处理，跨午夜的时间点应视为次日时刻。

### 2.2 事件数组

输入为二维数组结构：

```json
[
  [
    {
      "uid": "string",
      "record_date": "YYYY-MM-DD",
      "event_timestamp": "HH:mm",
      "event_type": "string",
      "type": "abnormal | intervention",
      "code": "string",
      "detail": {
        "trigger_cause": "string",
        "action_taken": "string",
        "result_summary": "string"
      },
      "related_event_id": "string",
      "sort_order": "number",
      "create_time": "ISO8601",
      "update_time": "ISO8601",
      "duration_sec": "number",
      "_id": "string",
      "language": "zh"
    },
    {
      "...intervention结构相同"
    }
  ]
]
```

---

## 3. 数据结构说明

### 3.1 外层结构

- 顶层必须是二维数组
- 每个子数组 = 一组事件链（event pair group）

### 3.2 内层结构

每组包含两类记录：

**（1）异常事件 `abnormal`**

`type = "abnormal"`，表示睡眠过程中的异常事件，例如：

- 噪音异常
- 心率异常
- 体动异常
- 入睡困难
- 噩梦应激

**（2）AI干预事件 `intervention`**

`type = "intervention"`，表示系统对异常事件的自动干预行为。

### 3.3 事件关联关系

异常事件与AI干预事件通过以下字段关联：

- `related_event_id`
- `abnormal` → `intervention` 一一对应
- `intervention` 必须指向对应 `abnormal`

---

## 4. 输出要求（强约束）

必须满足以下规则：

- 必须保持二维数组结构不变
- 必须保留所有字段
- 仅允许修改 `detail` 字段内容
- 不允许新增字段
- 不允许删除字段
- 不允许调整事件顺序

---

## 5. 可修改字段范围

仅允许修改以下字段：

- `detail.trigger_cause`
- `detail.action_taken`
- `detail.result_summary`

---

## 6. 重写规则

### 6.1 `trigger_cause`（诱因）

**定义**

描述事件触发的原因。

**写作规则**

必须满足：

- 语义上须表达"系统感知到某种异常信号"，但**禁止固定句式开头**：
  - 允许的语义方向（非固定模板）："检测到…"、"系统接到…"、"感知到…"、"识别到…"、"发现…"等，每次须变换使用
  - 禁止连续两条使用相同开头词
- 必须体现客观信号（生理 / 环境 / 行为）
- 语言平实自然，像日常说话一样，普通用户能看懂
- 禁止出现医学/生理学专业术语，例如"皮电"、"应激信号"、"自主神经"、"基线偏移"、"声学能量"等
- 描述的是"发生了什么"，不是"系统接收到什么信号"
- 必须避免原句结构复用

**示例表达风格**（仅参考，禁止复用原句，且须变换开头词）

- 检测到心跳加快，睡眠出现波动
- 系统接到室内突然出现噪音的信号
- 感知到睡眠状态变得不稳定
- 发现用户翻身次数明显增多
- 识别到环境温度出现异常变化

**禁止**

- ❌ 禁止出现"皮电"、"应激"、"基线"、"声学能量"、"自主神经"等专业术语
- ❌ 禁止使用让普通用户看不懂的医学或生理学词汇
- ❌ 禁止以"通知"结尾，例如"系统接到心率异常波动的触发通知"是不合规的，应改为描述发生了什么信号，如"系统接到心率持续偏高的异常信号"

### 6.2 `action_taken`（动作）

**定义**

描述系统对信号进行的分析或处理行为。

**写作规则（`abnormal` 异常事件）**

- 偏「分析 / 识别 / 监测」方向，语言平实，不要堆砌专业术语
- 例如：触发心率波动分析、开始监测睡眠状态、识别到环境噪音干扰

**写作规则（`intervention` AI干预事件）**

- 必须从声音、光线、气味（声 / 光 / 味）三个感官维度中选取一个或多个来描述干预动作
- 语言自然平实，描述实际发生了什么，不要使用晦涩术语
- 可以描述具体类型，如"白噪音"、"柔和灯光"、"舒缓香氛"，禁止出现品牌名或精确数值
- **干预内容必须与对应异常事件的类型相符**，不同事件类型干预方向不同：
  - 噪音类事件（`neighbor_*`、`nature_*` 等）：适合用白噪音"掩盖"外部声响
  - 心率类事件（`heart_rate_*`）：适合用舒缓音乐/轻音乐"平复/舒缓"心率，而非"掩盖干扰"
  - 体动类事件（`body_movement_*`）：适合用声音或气味帮助"放松/稳定"身体状态
  - 噩梦/情绪类事件（`nightmare`）：适合用声音、香氛组合"安抚情绪/平复状态"
  - 入睡困难类事件（`insomnia_*`）：适合引导放松、助眠
- **光照维度的使用限制（重要）**：根据 `event_timestamp` 与睡眠时间点的关系判断是否可使用光照：
  - 若 `event_timestamp` 落在 **`sleep_onset`（入睡时间）到 `out_of_bed`（起床时间）** 之间，即用户处于睡眠过程中，**禁止在 `action_taken` 中出现任何光照相关描述**（包括但不限于：调光、灯光、亮度、暖光、冷光、光线等）
  - 若 `event_timestamp` 落在 **`bed_time`（卧床时间）到 `sleep_onset`（入睡时间）** 之间，即用户处于入睡前期，可使用光照维度辅助营造入睡氛围
- **干预内容还必须结合 `event_timestamp` 所处的睡眠阶段**，不同阶段的干预目标和力度不同，详见第 7.4 节时段感知规则

**示例风格（`abnormal`）**（仅参考，不可复用）

- 触发心率波动分析
- 开始监测睡眠状态稳定性
- 识别到环境噪音干扰并启动分析

**示例风格（`intervention`）**（仅参考，不可复用）

- 播放轻柔白噪音帮助掩盖环境声响（适用于噪音类事件）
- 播放舒缓轻音乐辅助平复心率波动（适用于心率类事件）
- 调低灯光亮度，营造更适合入睡的暗环境
- 释放舒缓香氛辅助身体放松
- 结合轻柔声音与淡淡香氛引导情绪平稳（适用于噩梦/情绪类事件）

### 6.3 `result_summary`（结果）

**定义**

对事件或干预效果的最终结论。

**写作规则**

- `abnormal`（异常事件）：语义上须表达"最终判定为某种状态"，但禁止固定句式：
  - 允许的语义方向（非固定模板）："判定为…"、"确认为…"、"识别为…"、"归因为…"等，每次须变换使用
  - 结尾禁止出现"事件"二字
- `intervention`（AI干预）：语义上须表达"干预成功达到效果"，但禁止固定句式：
  - 允许的语义方向（非固定模板）："成功…"、"已实现…"、"有效…"、"达成…"等，每次须变换使用

**示例表达风格**（仅参考，不可复用原句）

- 判定为心率调节异常
- 判定为睡眠结构紊乱
- 判定为生理波动偏大
- 成功恢复睡眠稳定性
- 成功降低生理波动幅度
- 成功恢复睡眠连续性

**禁止**（仅针对 `abnormal`）

- ❌ 结尾不得以"事件"结束，例如"判定为心率调节异常事件"是不合规的，应改为"判定为心率调节异常"

---

## 7. AI干预事件特殊规则（`intervention`）

AI干预事件必须满足以下约束：

### 7.1 感官维度要求

`action_taken` 必须从声音 / 光线 / 气味（声 / 光 / 味）中选取至少一个维度来描述干预动作，表达要自然，让人一看就懂。

**重要**：所选维度及描述方式必须与对应异常事件类型相符。例如：
- 噪音类事件 → 可用白噪音"掩盖"干扰声
- 心率类事件 → 应用舒缓音乐"平复"心率，而非"掩盖干扰"（心率上升不存在外部干扰声）

**光照维度使用条件**：

| 事件时间点所处阶段 | 时间范围 | 是否可使用光照维度 |
|-----------------|---------|----------------|
| 入睡前期 | `bed_time` ～ `sleep_onset` | ✅ 可用光照辅助营造入睡氛围 |
| 睡眠中期 | `sleep_onset` ～ `wake_after_sleep` | ❌ 禁止出现任何光照描述 |
| 睡眠后期 | `wake_after_sleep` ～ `out_of_bed` | ❌ 禁止出现任何光照描述 |

睡眠过程中（`sleep_onset` 之后至 `out_of_bed` 之前）用户处于闭眼睡眠状态，光照干预无实际意义且可能造成打扰，**必须仅从声音或气味维度选取干预动作**。

### 7.2 禁止内容

禁止出现：

- ❌ 具体品牌名称（如产品品牌名、设备品牌名等）
- ❌ 精确数值（如分贝值、色温值）
- ❌ 设备型号或产品实现细节
- ❌ 晦涩专业术语堆砌

### 7.3 表达方向

- 用描述实际感受的语言，而非抽象系统术语
- 体现通过调节声音、光线或气味来帮助用户改善睡眠状态；三个维度可任意组合，出现顺序不限，也可只使用其中一个

### 7.4 时段感知规则

`action_taken` 必须结合 `event_timestamp` 与输入睡眠时间点（`bed_time` / `sleep_onset` / `wake_after_sleep` / `out_of_bed`）的关系，来决定干预的目标、力度和可用感官维度。

**睡眠阶段划分与干预规则：**

| 睡眠阶段 | 时间范围 | 可用感官维度 | 干预目标 | 力度与风格 |
|---------|---------|------------|---------|-----------|
| 入睡前期 | `bed_time` ～ `sleep_onset` | 声 / 光 / 味（三者均可） | 帮助用户放松、引导入睡 | 可以积极一些，侧重营造入睡氛围 |
| 睡眠中期 | `sleep_onset` ～ `wake_after_sleep` | 声 / 味（**禁用光照**） | 维持深睡眠，避免打断 | 极轻微，优先"维持"而非"调节" |
| 睡眠后期 | `wake_after_sleep` ～ `out_of_bed` | 声 / 味（**禁用光照**） | 保护剩余睡眠，防止完全清醒 | 轻柔克制，力度最小 |

**各阶段写作要点：**

- **入睡前期**：干预动作可描述为"播放…引导放松入睡"、"调低灯光营造入睡氛围"、"释放香氛帮助身体放松"，声光味三个维度均可使用
- **睡眠中期**：干预动作应体现"保持…不受干扰"、"维持…稳定"，仅可使用声音或气味；**不得出现任何光照描述**，避免使用"引导入睡"等入睡前期表达
- **睡眠后期**：干预动作应体现"帮助恢复平静"、"避免完全唤醒"，仅可使用声音或气味；**不得出现任何光照描述**，语气更轻，力度更小

## 10. 示例（仅用于理解，不可复用）

### 10.1 输入格式示例

```json
{
  "sleep_time_points": {
    "bed_time": "22:30",
    "sleep_onset": "23:05",
    "wake_after_sleep": "04:20",
    "out_of_bed": "06:45"
  },
  "events": [...]
}
```

### 10.2 `detail` 字段重写示例

**示例一：异常事件（`abnormal`）**

输入：
```json
{
  "trigger_cause": "检测到心率异常上升",
  "action_taken": "触发心脏状态分析",
  "result_summary": "判定为心率干扰影响"
}
```

输出：
```json
{
  "trigger_cause": "检测到心跳持续加快，睡眠出现波动",
  "action_taken": "触发心率波动分析，开始监测状态变化",
  "result_summary": "判定为心率调节异常"
}
```

**示例二：AI干预事件（`intervention`），事件发生在睡眠中期（01:30，位于 sleep_onset 23:05 ～ wake_after_sleep 04:20 之间）**

输入：
```json
{
  "trigger_cause": "...",
  "action_taken": "调低灯光亮度，播放舒缓白噪音",
  "result_summary": "..."
}
```

输出（睡眠中期，禁用光照，仅可用声音或气味）：
```json
{
  "trigger_cause": "...",
  "action_taken": "播放轻柔白噪音帮助维持睡眠平稳，避免环境声响造成干扰",
  "result_summary": "..."
}
```

> ⚠️ 注意：原 `action_taken` 中的"调低灯光亮度"属于光照描述，事件发生在睡眠过程中，**必须去除光照内容**，仅保留声音维度。

**示例三：AI干预事件（`intervention`），事件发生在入睡前期（22:45，位于 bed_time 22:30 ～ sleep_onset 23:05 之间）**

输出（入睡前期，声光味三者均可）：
```json
{
  "trigger_cause": "...",
  "action_taken": "调低环境灯光亮度，同步播放轻柔助眠音乐，帮助身体逐渐进入放松状态",
  "result_summary": "..."
}
```
