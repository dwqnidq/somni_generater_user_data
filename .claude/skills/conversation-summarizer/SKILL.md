# 会话总结技能

将当前对话的核心内容压缩为一个结构化的 markdown 文档，只保留关键信息，丢弃冗余细节。

## 输出格式

生成的 markdown 文件结构如下：

```markdown
# 项目会话总结 (YYYY-MM-DD)

## 项目概述
一两句话说明项目是什么、在做什么。

## 关键改动
列出本次会话中实际修改的文件和改动要点，每个改动用简短的标题 + 一句说明。

## 发现的问题
如果有未解决的问题或新发现的 bug，列出编号和一句话描述。

## 关键文件清单
| 文件 | 作用 |
|------|------|
| path/to/file | 一句话说明 |

## 工作偏好
用户表达过的协作偏好（如"不需要确认直接修改"）。
```

## 总结原则

1. **只保留动作和结果** — 不保留过程讨论、反复确认、中间状态
2. **改动要具体** — 写清改了哪个文件的哪部分，改成了什么
3. **问题要可操作** — 每个问题有明确的现象和可能的根因
4. **省略已解决的调试过程** — 只写最终修复方案，不写"先试了A发现不行，又试了B"
5. **文件清单只列关键文件** — 不列配置文件、临时文件、输出文件
6. **用户偏好单独记录** — 这是跨会话有价值的持久信息

## 执行步骤

1. 回顾当前对话的所有内容
2. 识别项目名称和当前日期
3. 提取所有实际执行的代码修改（文件路径 + 改动内容）
4. 提取发现但未修复的问题
5. 提取用户表达的工作偏好
6. 按照输出格式组织为 markdown
7. 写入 `docs/session_summary_YYYYMMDD.md`（项目根目录下的 docs 文件夹）
8. 告知用户文件已生成

## 注意事项

- 文件名用当天日期，如 `session_summary_20260430.md`
- 如果 docs 目录不存在，先创建
- 如果已存在同日期的文件，询问用户是覆盖还是追加
- 代码改动部分可以包含关键代码片段（3-5 行以内），但不要贴完整函数
- 使用中文撰写
